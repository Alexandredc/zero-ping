Local GitHub triage for lead devs

Silence the pings.
Keep what needs you.

Zéro Ping replaces GitHub notification emails with one sorted list of what waits on you: reviews, replies, your pull requests and your team’s, each with its Slack threads. It runs on your machine.

Run it locally View on GitHub

Open source · No account · Data in a local database

Why

The ping that matters arrives with all the ones that don’t.

As a lead dev, every review request, mention, CI run, dependency bump and Slack thread about a PR lands on you. Zéro Ping reads them all, files the noise, and keeps what waits on you, ranked by a score it explains. It never files away something that waits on you.

The inbox

One list, sorted by what to do next.

A score you can open. Each item’s priority adds up its age, a missing last reviewer, size, CI, urgent labels and the urgency Jev estimates.

GitHub and Slack side by side. Read the conversation with the Slack threads that cite the PR, or the diff with its file tree and Viewed boxes synced to GitHub.

Act without leaving. Reply, approve, request changes, mark as done or snooze, one item or a batch.

Four folders, and nothing else in your way

À reviewer
Open PRs where your review is still requested, directly or through your team. When you asked for changes and new commits arrive, the PR comes back, and the diff can show only those commits.
On t’attend
Mentions and review threads where someone answered after you.
Mes PR
Your open PRs with CI and review decision. Merge with the method you pick, read failing jobs with their log, re-run the failed GitHub Actions jobs.
Équipe
PRs in watched repos with no reviewer, changes requested, red CI, conflicts or open too long. Take the review in one click.

Around the inbox

  • AI summaries. Short, standard or detailed, from the GitHub conversation and the Slack threads found. Saved, and flagged when newer activity makes them stale.
  • Ask about a PR. The AI gets the conversation, Jev’s KPIs, the project status and priority, the uat deploy state and the diff.
  • Slack threads. An agent finds the messages that cite a PR using your own Slack access, shows full threads, and posts your reply in the thread when you send one.
  • AI review in one click. @codex review, @claude review or /gemini review, configurable.
  • Daily recap. Each working day at the time you choose, a notification sums up what waits on you and /standup:team drafts the standup in Slack.
  • Your issues. The current sprint of your GitHub project, with status, priority and Jev urgency.
  • Overview. Review delay, your Zéro Ping streak, and what came in and went out each day.
  • A ping counter. What waits on you shows on the sidebar logo, the tab title and the favicon. At zero, it all disappears.
  • Notifications, on your terms. Review requests, replies, changes requested or red CI on your PR, with do-not-disturb hours.

Local and private

Nothing to host. Nothing to sign up for.

Your machine
A Node server on localhost and an embedded PGlite database in the repo’s .data folder.
Your GitHub token
It reuses gh auth token (or GITHUB_TOKEN) and polls at GitHub’s pace with If-Modified-Since, so unchanged checks cost no quota.
Your AI
Summaries, questions and Slack search run through your own Claude Code or Codex CLI, non-interactively, on your account.
Your Slack access
Search is read-only. A message is posted only when you send a reply from the app.
Optional scoring
With a TypeSafe key, Jev estimates urgency when an item’s content changes. Without one, deterministic rules rank the list.

Quick start

Running in four commands.

You need

  • Node.js 22.12 or later, and pnpm
  • The GitHub CLI, signed in with gh auth login (or a GITHUB_TOKEN)
  • For AI and Slack: Claude Code with the Slack connector, or Codex with a Slack MCP server
  • Optional: a TypeSafe API key for Jev scoring

  1. Clone the repository

    git clone https://github.com/Alexandredc/github-management.git
cd github-management

  2. Install the dependencies

    pnpm install

  3. Create your .env, and add TYPESAFE_AI_API_KEY if you have one

    cp .env.example .env

  4. Start it, then open http://localhost:3000

    pnpm dev

The first sync fetches the last 30 days of notifications. On macOS, scripts/macos-app.sh creates a Dock app that starts the server on port 4747 and shows your ping count on its badge.
